## 一、做了什么（按任务书编号）

### P0-A 上下文隔离与「答非所问」

**根因**：议会/团队把父会话（普通聊天）里的历史资料无条件塞进提示词；团队还把资料
存在**会话级** `TeamState.context` 上，一次交代就污染之后每一条消息。

- 新增 `app/lib/collab/collab_intent.dart`：`CollabIntent` + `CollabIntentRules`（问候/讨论/
  执行/确认的纯规则）+ `CollabContextPolicy`（`allowsHistory` / `gate` / `explain`）。
  **只有明确指代**（上面/前面/刚才/那个方案/继续/消息 #3…）才允许读历史。
- `CollabContextPack.build(allowHistory:)` 在第一行收口；不允许时直接给空包。
- 团队：`TeamMsg.context` 取代会话级字段，资料只跟着**那一条**用户消息；`send()` 写入前
  过 `CollabContextPolicy.gate`；`_prompt` / `_planPrompt` 都用这条消息自己的资料。
  旧数据在 `TeamState.fromJson` 里迁移：会话级 `context` 归到最后一条没带资料的用户消息，
  然后清空，**一条消息都不删**。
- 议会：`CollabOrchestrator.withGatedContext(spec)` 在 `submit()` 入口清掉不允许的
  `context` / `sourceMessageIds`。
- 席位子会话边界：新增 `app/lib/collab/seat_sessions.dart`，按
  `conversationId + seatId + provider + model + sessionId` 五元组复用，随会话落盘
  （`CouncilConversation.seatSessions`），换模型/换会话不会串号。
- 新增 `app/lib/council/council_request.dart`：`CouncilRequestKind.social` 不进主席综合、
  不要求 200–400 字，提示词改成自然回应。

### P0-B 团队请求分流

- 新增 `app/lib/team/team_request.dart`：`routeTeamRequest()` 返回
  `TeamRequestKind`（social / discussion / execution / mentioned / clarification）。
- 「你们好」→ 全体成员依次自然回应，**绝不**进 `_planPrompt()`。
- 设了主管时，非社交消息由主管作为普通成员先答（保持团队原有交互）；只有执行类才拆任务图。
- 级联（`@` 转交）只在非社交轮保留，寒暄不会互相甩锅。

### P0-C 流式正文 / 思考 / 工具

- `DshCollabDriver.streamTurn()` 重写：attempt 过滤历史回放；`ReasoningDeltaChunk`
  累积成 `CollabTurnThought`；`ToolCallEvent` / `ToolResultEvent` 发真实工具名、
  真实状态与失败原因；`AssistantMessageEvent` 立即以 `replace: true` 进 UI。
- `runTurnObserved()`：`CollabActivity` 新增 `reasoning` / `tools`；工具按 callId
  就地更新（一次调用只占一行）；终稿与增量不一致时**替换**，收尾再校准一次。
- `collab_kit.dart`：`CollabMessage` 的 footer 同时渲染 `ThinkingPill(reasoning:)`
  与新的 `CollabToolTrace`（真实工具名 + 状态，最多 4 行）；每个成员各画各的，不串线。

### P0-D 协作聊天被输入栏遮挡

- 抽出 `app/lib/ui/chat/shared/follow_scroll.dart`（原 `ChatList._FollowPhysics`），
  `ChatList` 与 `CollabTimeline` 共用；**同一条消息变长**（Markdown/代码块/表格/思考/工具行）
  在同一次布局里贴住末尾。
- `CollabTimeline` 加 `physics` + `ScrollMetricsNotification` 兜底；用户上翻时不抢滚动。
- `EdgeFade` 新增 `bottomTail`；协作时间线传 0（视口已停在输入栏上沿，原来
  「输入栏高度 + 48dp」的淡出会把最后几行正文整段淡掉）。

### P0-E 底部空间不再重复计算

- `ShellMetrics.navHeight` 60 → 56（48 触控 + 4×2 玻璃内边距），新增 `navPadding = 4`；
  `BottomNav` 用同一个常量。
- `sessions_page` 去掉与外壳 `Padding(bottom: lift)` 重复的整条导航高度占位，只留 8dp。
- 外壳、页面、输入栏、消息区现在用的是同一个 `ShellMetrics.extentAt(...)`。

### P0-F / P0-G / P0-H 历史体验

- 空议会（`hasUserQuestion`）/空团队（`hasUserMessage`）不再占历史位置，配置与草稿仍保留；
  运行中只要发过一条真实消息就立刻出现。
- 协作历史行改为复用普通 `SessionTile`：同一行高 / 字号 / 基线 / 选中高亮，只多一枚
  「议会」「团队」小标签（`kindTag`），`currentConversationRef()` 判断当前选中。
- 长按改为**详情操作面板**（`showCollabEntrySheet`）：标题、类型、成员数、创建/更新时间、
  状态、失败原因、最近一条提问与回答；操作含打开原会话、重命名、导出 Markdown、
  继续未完成的运行、删除（二次确认）。

### P0-I / P0-J 身份与快速恢复

- `ConversationRef` / `openConversation()` 身份链路未改，新增两组交叉序列回归
  （议会A→普通B→团队C→普通A；团队A→议会B→普通C）。
- `TeamOrchestrator.peek()` / `CollabOrchestrator.peek()` 暴露进程内快照；议会页
  `_loadTurns` 改成两层：先贴正在跑的那一轮（内存快照，2 秒兜底），再后台补齐其它回合；
  团队页优先用 `rev` 更新的内存快照。不重发原问题、不重复驱动已完成成员。

### P1-A / P1-B 视觉占位

- `IdentityBar`：上下内边距 9/13 → 4/7，圆形主机图标 36 → 33（左侧补 4.5 让头像仍在 20 线），
  44dp 触控全部保留（主机详情、主机切换、全部功能、设置）。
- 底部导航：玻璃内边距统一为 4，四入口、自动收缩、键盘联动都保留，触控 48dp。

## 五、实机验收（录屏 A–E）

安装：优先下 `.zip` 解压后装里面的 APK（直链 APK 在手机上容易下断，尾部缺字节等于没签名）。
覆盖安装不需要卸载，`applicationId` 与签名都没变。

| 视频 | 操作 | 期望 |
| --- | --- | --- |
| A 普通问候 | 普通聊天里贴一段方案/仓库地址 → 切议会 → 发「你们好」 | 每位成员各回一句自然问候；**不**提那段方案，不写「结论/共识/分歧」；无主席综合 |
| B 历史记录 | 新建一个团队但不发言 → 打开历史；再进去发一句「你们好」→ 回历史 | 没说话时不出现；发过一句立刻出现，行尾有「团队」标签，点开能回到原会话 |
| C 模式切换与恢复 | 团队里发一个会长跑的任务 → 立刻切到普通聊天 → 再切回团队/从历史打开 | 立刻看到当前成员与已生成正文，不用等盘；不重发原问题、不重复调用已完成成员 |
| D 消息遮挡 | 协作里让成员输出长 Markdown（代码块 / 表格 / 工具行） | 最后一行始终在输入栏上方；往上翻看历史时不被强制拉回底部 |
| E 底部空间 | 在历史页/协作页上滑收起导航，再下拉/键盘弹起 | 导航收起时主体跟着抬高、没有一条空白带；键盘收起后导航回来、输入栏不被挡 |

长按一条协作历史：应弹出详情面板（类型/成员/时间/状态/最近一问一答 + 打开、重命名、
导出、继续、删除），不是直接问「删不删」。

# 融合设计：从 21 个开源 DSH 衍生项目到「子川助手」

> 调研方法：`git clone`/codeload 拉取 21 个仓库（只读 README、`package.json`、`cordis.patch.yml`、`dsh.plugin.json`，不读 `node_modules`、不执行仓库里的任何安装脚本），再用 **craft-anything** 对其中 3 个做源码级静态分析（`js-app-map`），并对自己实现的 App 做运行时取证（`web-site-open` / `web-page-screenshot-take`）。
> 数据：`research/matrix.md`（总表 + 21 小节 + 共性优缺点 Top10）、`research/craft-anything-report.md`（证据账本报告）。

## 一、生态里到底在比什么

21 个项目可以归成 5 个「面」，每个面都有明确的赢家特征：

| 面 | 代表项目 | 赢家特征 |
|---|---|---|
| 交付面（在哪儿用） | dsh-Go、dsh-TUI、dsh-desktop ×2、deepseek-harness-desktop | 同一个引擎，多端复用；移动端靠 PRoot/原生插件协议 |
| 工作台面（怎么干活） | my-deepseek-harness、DSH-better-sidebar | 文件/终端/Git/浏览器与对话同屏，人类通道与 Agent 通道分离 |
| 协作面（谁来干） | Tandem、DS-Bot、swarm-panel | 多 Agent 有组织结构、有可观测拓扑，而不是黑箱并发 |
| 治理面（花多少、装什么） | dsh-context、dsh-ops、token-monitor、dsh-market、dsh-purge | 上下文/成本可观测；安装可逆、可回滚 |
| 表现面（怎么答） | dsh-genui-enhanced、dsh-im | 富组件渲染、外部入口接入 |

共用的技术骨架只有一句：**`dsh.bundle.patch`（`cordis.patch.yml` 的 `insert` 行）+ `dsh.client` 声明**，不改上游就能把自己的 host 能力与浏览器 UI 装进 profile。craft-anything 对 market 的静态分析（341/392 文件、esbuild、167 endpoints、67 routes）和 better-sidebar（500/584 文件、46 endpoints、267 routes）都是这条骨架的实例。

## 二、被吸收进本应用的 16 个设计点

|---|---|---|---|

| 3 | murongg/daban | Bot 广场式的「角色预先定义」 | 8 个任务模板（写功能/修 Bug/跑构建/操作手机/深度调研/逆向分析/多智能体/交付报告） |

## 三、针对「共性缺陷」的对策

| 缺陷（生态实测） | 本应用的做法 |
|---|---|
| 版本地狱（插件钉死宿主小版本） | 只用公开 API（`slots` / `inject` / `tools` / `webServer` / `systemPrompt`），`engines.dsh >= 0.2.2-rc.1`，不读内部字段 |
| 安装路径混乱（npm/link:/tgz/索引） | 一个 `install.sh`：拷 bundle → 建软链 → 写依赖 → 追加 bundle 行，幂等可重复 |
| CLI profile 与桌面 profile 割裂 | 文档写明「装在哪个 profile 就只在哪个 profile 生效」，卸载脚本按 profile 走 |
| 权限默认偏松 | `/zichuan/api/build` 有命令白名单 + 单并发 + 超时上限（默认 5 min，硬顶 10 min）；`allowHttpBuild` 可一键关掉 |
| 「装好了」缺少可信信号 | `GET /zichuan/api/ping` 自证；面板四指标活数据；构建按钮本身就是端到端自测 |
| 反馈回路长（要硬刷新/重装） | `#zichuan` 深链 + `Alt+Z` + 面板自带刷新；客户端无构建步骤，改完只重启宿主 |
| 单实例槽位冲突导致页面异常 | 槽位注册在 `window` 上幂等去重，并对「已被占用」安静让位（冷启动实测 0 未捕获异常） |

## 四、为什么没有再抄这些

- **不做第二个侧栏**（better-sidebar 已很好）：重复造侧栏会跟官方 sidebar 抢位置，收益低、冲突高。
- **不做插件市场客户端**（官方 `dsh-market` 已覆盖）：本应用只保证自己可装可卸。
- **不做上下文仪表盘**（dsh-context 更专业）：面板只保留四个能自证的运行指标，不复制投影解析。
- **不做多 Bot 常驻进程**（DS-Bot 的重量级形态）：用 subagent + 任务模板拿到 80% 收益，保持单进程轻量。

## 五、实测证据

- 运行时：craft-anything `web_site_open` + `web_page_screenshot_take`（证据 id 见 `research/craft-anything-report.md`），面板渲染 8 模板卡 / 4 指标 / 4 胶囊，冷启动 console 0 异常。
- 构建：面板点 `node -v` → `PASS · exit 0 · 177ms · v24.22.1`。
- 接口：`/zichuan/api/status` 返回 `{name:"子川助手", version:"1.0.0", profile:"web", node:"v24.22.1", diskFreeGb:{sdcard:74.8}, ...}`；`rm -rf /` 被白名单拒绝（403）。

## 一、S1 底部导航与输入栏收缩（P0）

### 1.1 根因

`TabShell._onScroll()` 直接读 `ScrollUpdateNotification` 的像素差：

- **分不清来源**。`animateTo()`、`jumpTo()`、流式跟随、`correctPixels`（Markdown 变高）都会产生同样的 `ScrollUpdate`，于是「没滑也收」「流式输出把导航带走」。
- **只看单次 delta**。一次 2dp 抖动 + 一次 3dp 抖动会各判一次方向，来回轻微移动就连续开合。
- **没有「回到底部」的兜底**。拖到最新消息后导航仍躲着。
- **收起时安全区一起归零**。`extentAt = (nav + gap + safe) * t`，`t=0` 时页面铺到屏幕最底，输入栏压在手势条下面。

### 1.2 改法

新增 `app/lib/ui/shell/nav_collapse.dart`：`NavigationCollapseController` 成为唯一判定入口。

| 规则 | 实现 |
| --- | --- |
| 只认用户手势 | 只有 `ScrollUpdateNotification.dragDetails != null` 才累计；程序滚动只更新基线 |
| 双阈值迟滞 | 向下累计 **24dp** 收起、反向 **12dp** 展开；达到阈值后本段手势结算，要再走满一个阈值才会再变 |
| 忽略嵌套滚动 | `depth > 1` 直接丢弃（代码块内滚动区、卡片里的横向行） |
| 接近底部强制展开 | `metrics.extentAfter <= 48` 时立即展开 |
| 拖到顶展开 | `OverscrollNotification` 且 `pixels <= 0` |
| 键盘 | 弹起立即收；收起延迟 **120ms** 展开（避开输入法动画） |
| 换标签/换会话 | `reset()` 立即展开并清掉手势残量 |
| 其他页面 | 任务/工具/设置的滚动不参与（`_onScroll` 先看当前标签） |

动画仍只有一条 `_reveal`：导航位移、页面抬升、列表留白共用同一个进度，不存在两个控制器抢同一段底部几何。

`ShellMetrics.extentAt` 改为 `safeBottom + (navHeight + navGap) * t`：**收起时安全区不消失**，输入栏不会压住手势条。

### 1.3 测试

`test/shell/nav_collapse_test.dart`（12 个用例）：24dp 收起 / 12dp 展开 / 1–3dp 抖动不触发 / 流式自动滚动不触发 / animateTo-jumpTo 不触发 / 恢复位置不触发 / 距底 48dp 强制展开 / 拖到顶展开 / 键盘开合时序 / 键盘期间滚动不算 / 待展开被继续下滚取消 / reset。

`test/shell/tab_shell_test.dart` ⑤ 按新规则调整：窗口 520、位移 120（原 260 会直接拖到底，触发强制展开——这是任务书 2.6 要的行为，不是回归）。

## 二、S2 首页、设置页与输入栏（P0）

### 2.1 首页建议自动换行

`SuggestionChips` 从 `SizedBox(40) → SingleChildScrollView(horizontal) → Row` 改成 `Wrap`：间距 8、内容定宽、放不下自动换行，不再需要横滑；仍是小胶囊（不退回 2×2 大卡片）。

已验证：390dp 下四项换行且每枚都在输入栏右缘以内；260dp 下多行；2 倍字号不截断。

### 2.2 设置页三处

| 问题 | 改法 |
| --- | --- |
| 长模型名把标题压成竖排 | `SettingsTile` 给 value 加 `ConstrainedBox(maxWidth: 58% 行宽)` + `DefaultTextStyle(maxLines: 1, overflow: ellipsis, textAlign: end)`；标题 `maxLines: 1` + ellipsis |
| 两个「模型」入口 | 删掉「模型与协作」分组里的 `SettingsTile`，只保留顶部「当前配置」卡的 `_ConfigRow`；搜索锚点 `SettingsPageId.models` 移到这一行，仍可定位 |
| 主设置页出现返回箭头、顶部空白大 | `AppPage` 新增 `showBack`（默认 true）；设置页传 `false`，标题上间距 56 → 42 |

`test/ui/settings_tile_text_test.dart`：320dp + 100 字符模型名、2 倍字号、短值三种情况，断言标题宽度 > 24（不是竖排）、值不越过行右缘、短值只占自然宽度。

### 2.3 输入栏

| 项 | 结果 |
| --- | --- |
| 普通聊天占位 | `给 DSH 发消息…` → **`给知川发消息…`**（英文 `Message Zhichuan…`），走 `parts/chat_*.arb` + `tool/l10n_merge.py` 重新生成 |
| 团队占位 | `说点什么，@ 一位队友` → **`给团队发送消息…`** |
| 议会占位 | `向议会提问，成员会各自作答` → **`向议会提问…`** |
| 「1 个已连接」常驻胶囊 | 当前代码中不存在（v4.2 改造已移除）；输入栏上方只剩插件/快捷胶囊，且随 `visible` 折叠 |

## 三、S3 协作流式（P0，验证 + 批处理）

v4.3 的 `DshCollabDriver.streamTurn` 已经区分 attempt、累积 reasoning、发真实 `tool/call` 与 `tool/result`、用完整消息替换增量、终稿再校准。本轮补的是**上屏节流**：

- `council_page`：事件回调里的 `setState` 合并到 **32ms** 一次（约 30fps），终态（done/failed/cancelled）立即刷。
- `team_page`：同样 32ms 合并，`running.isEmpty` 时立即刷。

这样每个 token 不再重建整个时间线；顺序接力、成员隔离、终稿去重逻辑不变。

## 四、1.4 取消调用次数硬预算

`CollabOrchestrator` 原来在每次 `_runSeat` 前检查 `callsUsed >= spec.budgetCalls`，超出即 `failed`（「预算用尽」）。现在：

- 删除该闸门与 `_BudgetExceeded`；
- `callsUsed` 继续计数，只在导出/展示里用；
- `_validate` 不再校验「预算 ≥ 预计调用」；
- `CouncilSpec.budgetCalls` 字段保留（兼容已落盘 JSON），但不再参与终止判断。

防死循环保护仍在：单席位最多 2 次尝试、返工 `attempts <= 2`、级联 `depth < 2`。

测试改为「budgetCalls=2 但实际 4 次调用，运行仍 done」。

## 五、7.5 默认团队角色

新建团队时不再叫「队友 1/队友 2」，默认按角色模板给两位：

| 顺位 | 名字 | 简介（进入主管规划提示词） |
| --- | --- | --- |
| 1（主管） | 队长 | 负责拆解任务、分派队友、审核并汇总最终结果 |
| 2 | 研究员 | 查资料、读代码、把事实、约束和风险讲清楚 |

另备「实现者」「审查者」两个角色模板（成员抽屉里可继续加人）。名字、头像、模型、思考深度都可改并落盘。

## 八、遗留 / 下一步

1. **输入栏「紧凑小条」形态**：当前 Composer 常态就是单行胶囊（≈52dp），导航收起时它跟随下移、保持可点与草稿；没有再压一层（再压会低于 44dp 触控下限）。若产品仍要「收起成小条」，需要单独设计一版 compact Composer。
2. **冷启动首帧快照**（任务书 10.3）：进程内 `peek()` 已能秒开正在跑的会话；跨进程冷启动仍走 `CollabStore` 读盘（首帧实测 150–400ms）。`ConversationRenderSnapshot` 的持久化方案尚未落。
3. **统一时间线 `ConversationTimeline`**（任务书九）：本轮只对齐了数据与交互（思考/工具/滚动/历史行），`ChatList` 与 `CollabTimeline` 仍是两个容器，按任务书 9.5「先抽能力再迁移」保留。
4. **MotionPolicy 全量扫描**（任务书十三）：未做控件级扫描测试。
5. **实机验收 A–H**：沙箱无设备，需要在真机上录。

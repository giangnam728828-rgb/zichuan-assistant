## 一、第一轮：S1 / S2 / S3（部分）/ S5

对应录屏里能看见的四个退步。

### S1 引擎反复需要启动（已改）

**根因**：`PerformanceDefaults.resolve()` 里 `autoStartLocal: !light`。
`light` = 低端机档位 **或** 发热降级。手机被判定为低端（vivo 中端机基本都会）
或机身发热时，自动启动被默认关掉，冷启动必然停在「引擎未运行 / 启动引擎」。

**改法**：`autoStartLocal: true`，与性能档位彻底解耦。用户显式关掉仍然生效
（`autoStartLocalExplicit`）。

**验收**：冷启动不点按钮，引擎自动进入 ready；设置顶部卡片不再显示「已停止」。

### S3 动效消失（第一轮只修到「档位不再归零」）

**根因**：`app.dart` 的 builder 把 `MediaQuery.disableAnimations` 写成
`系统减少动画 || performance.reduceMotion`，而 `reduceMotion = !(prefs.animations ?? !light)`。
结果是「低端机档位」等于「全局关闭动画」——页面转场、按钮反馈、菜单展开全部归零，
不只是装饰动效。

**第一轮改法**：`reduceMotion = prefs.animations ?? false`。档位只继续降装饰层
（`fluidMotion` / `tilt` / `petEnabled`），基础动效（转场、按压、菜单）保留。

**但这里埋着一个方向错误**：开关的 `value` 写的是 `!reduceMotion`，`onChanged`
把 `true` 存进 `prefs.animations`，而 `reduceMotion = prefs.animations ?? false`
又把它读成「要减少」——打开开关反而关掉动画。第二轮已修。

### S2 开屏消失（部分改）

**已做**：`LaunchController.begin()` 的 `catch` 以前直接 `return null`，静默丢弃。
现在会打印 `[dsh-launch] native begin failed: …`，并用默认品牌画面兜底播一轮。

**未确认**：录屏里「冷启动完全没有开屏」还可能是原生侧把这次启动判成了热启动
（`LaunchSnapshot` 返回 null 或 `coldEngine=false`）。必须看真机日志才能定：
`adb logcat | grep dsh-launch`。拿到日志前不再改开屏时间线。

### S5 左上角历史入口（已改）

顶栏左侧由 `≡` 改为历史图标，点击直接切到「历史」标签
（`switchTab(context, RootTab.history)`），底部「历史」标签保留，符合 D1 决策。
宽屏侧栏的 `≡` 逻辑不动。

## 二、第二轮：S3 完整（三档模型）

### 2.1 新增 `MotionPolicy`

文件：`app/lib/performance/motion_policy.dart`

```
MotionTier.essential   状态本身：加载、进度、成功/失败提示
MotionTier.standard    结构变化：页面转场、菜单展开、列表进出、按压反馈
MotionTier.decorative  纯装饰：灵动动效、陀螺仪光斑、背景呼吸、宠物
```

三个输入互相独立：

| 输入 | 来源 | 影响 |
|---|---|---|
| `systemReduced` | 系统「移除动画」 | 三档全关（无障碍最高优先级） |
| `userMuted` | 设置 → 性能 → 动画 | 只留 essential |
| `lightweight` | 低端机 / 发热降级 | 只改装饰档的**默认值**，不硬关 |

装配点只有一处：`app.dart` 里 `performance.motion.withSystemReduced(...)`，
随后同时注入 `MotionPolicyScope` 与 `MediaQuery.disableAnimations`（后者给 Flutter
自己的路由、滚动、弹层用）。

### 2.2 `PerformanceDefaults` 的契约变化

- 新增 `motion` 字段；
- `reduceMotion` 从字段改成派生 getter（`!motion.allows(standard)`），
  所以低端机不再让它为真；
- 诊断 map 增加 `motion` 子对象，保留旧字段以免既有诊断脚本读不到。

### 2.3 修掉开关方向

`prefs.animations` 存的是「开」（`setAnimations(true)`），读取改为
`prefs.animations == false`。之前 `?? false` 把「关」读成「不减少」，开关是反的。

### 2.4 守卫测试

- `test/performance/motion_policy_test.dart`：三档真值表、`withSystemReduced`、
  `PerformanceDefaults` 派生（低端机保留标准档、仍可手开灵动）。
- `test/performance/motion_scan_test.dart`：扫描 `lib/`，除 `app.dart`（唯一合并点）、
  `launch_overlay.dart`（开屏在 MaterialApp 之前）外，禁止直接读
  `accessibilityFeatures.disableAnimations`；禁止再把 `reduceMotion` 当总闸。

结果：12 项全过；`flutter analyze` 0 error / 0 warning。

## 四、2.0.2 的两个坑（已修）

1. **包内版本号是 2.0.0**：根目录 `build-apk.sh` 把 `VERSION_NAME` 写死成 `2.0.0`，
   CI 没有传这个变量，于是 v2.0.2 的 release 资产叫
   `zichuan-assistant-2.0.0.apk`，APK 内 `versionName` 也是 2.0.0。
   tag、发布说明、设置页三处对不上；versionCode 仍是构建分钟，能覆盖安装，
   但更新检查会认错版本。现在默认值改为读 `app/pubspec.yaml`。
2. **l10n 分片丢键**：`parts/bots_*.arb` 少了 9 个房间模式键，重跑
   `tool/l10n_merge.py` 会把它们删掉，随后 analyze 报 12 个 `undefined_getter`。
   已补回分片，合并后 8434 键、零丢失。

## 五、发布纪律（vivo）

- **给用户的链接一律优先 ZIP**：600MB+ 的 APK 直链在手机上容易断在半路，
  APK 的 v2 签名块在文件最末尾，尾部一缺就等于没有签名，vivo 报
  「套件似乎无效／安装组件欠缺开发人员证书」。
- CI 仍强制校验「v1 + v2 在、v3 不在」，并产出 `SHA256SUMS.txt`。
- 签名材料只在 Secrets，仓库里不再有 keystore 与口令；因要保留覆盖升级，钥匙未轮换。

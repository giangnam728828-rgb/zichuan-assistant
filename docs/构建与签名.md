# 构建与签名（实测记录）

## 为什么必须固定签名

Android 用签名证书确认「同一个应用」。换成临时/debug 签名，系统会拒绝覆盖安装，只能先卸载——数据、登录态、缓存全丢。所以要一把**长期不变**的 key。

本仓库的 key：

| 项 | 值 |
|---|---|
| 文件 | `keystore/zichuan-release.jks` |
| 别名 | `zichuan` |
| 算法 | RSA 2048 / SHA384withRSA |
| 有效期 | 10000 天，至 2054-04-07 |
| 证书 SHA-256 | `05d1265d870c5b72e53c8a745dbe8fe12edb791ea17f7bdaf40234904c4d5057` |
| 证书 SHA-1 | `6310a44838d0364839b3d95de27e4f3f1c71ee53` |

## 实测：两次构建签名一致

```
dist/zichuan-assistant-1.0.0.apk: 05d1265d870c5b72e53c8a745dbe8fe12edb791ea17f7bdaf40234904c4d5057
dist/zichuan-assistant-1.0.1.apk: 05d1265d870c5b72e53c8a745dbe8fe12edb791ea17f7bdaf40234904c4d5057
```

`versionCode` 分别是 1 和 2，签名者相同 → `adb install -r` 可直接覆盖。

CI 里还有一步硬校验：签名指纹与上面这个常量不一致就直接 fail，避免有人误用新 key 把覆盖安装链弄断。

## 本机（arm64 proot）构建时踩到的两个坑

1. **官方 build-tools 只有 x86_64**：`aapt2`、`zipalign` 都是 ELF x86-64，在 aarch64 上 `cannot execute: required file not found`。改用发行版 `aapt` / `zipalign` / `apksigner`（`apt install aapt apksigner zipalign`），`d8` 继续用 build-tools 里的脚本（它只是一层 `java -cp lib/d8.jar` 包装，架构无关）。
2. **d8 8.2 对匿名内部类崩溃**：`Error in MainActivity$1.class ... NullPointerException: String.length()`。把 `new WebViewClient(){…}` 改成静态内部类 `Client` 后正常。用 `--release 8` 编译，dex 产出稳定。

## 连接故障与修复记录（1.0.4）

用户现场出现 `dsh web authentication required; reopen the URL printed by dsh web.`。本机 DSH 诊断确认 Web 服务启动在 `127.0.0.1:3080`，启动输出打印的是带 token 的完整 URL；之前 APK 把裸根地址当默认值，而且 `onPageFinished` 无条件隐藏错误视图，所以认证页被呈现成近乎空白的黑屏。

1.0.4 修复：首次启动显示连接设置页；指引用户到 DSH-Go「设置 → 本机引擎 → 日志」复制 `dsh web:` 后的完整 URL；检测到认证提示时回到配置页并说明原因；连接成功后保留可见的「连接设置」按钮；不在页面错误中显示或写日志输出完整 token。连接地址存放在应用私有 SharedPreferences。

## 真机验证状态

构建环境没有可连的 adb 设备（`adb devices` 为空），所以新版尚未在你的手机上安装验证。APK 编译、结构与签名可验证；你装上新版后，粘贴完整 URL 即可完成连接。
